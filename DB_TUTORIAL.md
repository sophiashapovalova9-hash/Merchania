# Как подключить SQL Server к бэкенду — туториал для чайника

Читаешь сверху вниз. Способ А (Docker) проще — начни с него, даже если Docker
кажется страшным. Способ Б — если Docker совсем не хочется.

---

## Часть 0. Что вообще значит «подключить базу»

Смотри на цепочку:

```
браузер  →  фронтенд (React)  →  бэкенд (Express, порт 4000)  →  SQL Server (порт 1433)
```

Бэкенд — это прослойка. Фронтенд ходит в него по адресу `/api/...`, а бэкенд ходит
в базу данных и таскает оттуда товары, заказы и т.д. Чтобы бэкенд знал, **куда и с каким
паролем** стучаться, у него есть файл `backend/.env` — это его «настройки подключения».

Сейчас в `.env` стоит `MOCK_DB=true`. Это тумблер «работаем без базы, данные из памяти».
Подключить настоящую БД = сделать две вещи:

1. Чтобы SQL Server **был запущен** и в нём была база `ArtistMerchDB` с таблицами (способ А или Б).
2. Сказать бэкенду «теперь работаем по-настоящему»: в `.env` поставить `MOCK_DB=false`
   и правильные логин/пароль. **После правки `.env` бэкенд надо перезапустить**
   (остановить `npm run dev` и запустить заново) — настройки читаются при старте.

Проверка в любой момент: открой <http://localhost:4000/api/health>

- `"mode": "mock"` — база НЕ подключена, бэкенд сидит на заглушках;
- `"mode": "mssql", "connected": true` — подключена, всё хорошо;
- `"mode": "mssql", "connected": false` — бэкенд хочет в базу, но не достучался —
  читай часть 4.

Ключи `.env`, которые тебе понадобятся (все уже есть в `.env.example`):

| Ключ | Значение | Что это |
|---|---|---|
| `MOCK_DB` | `false` | выключить заглушки |
| `DB_SERVER` | `localhost` | где стоит SQL Server |
| `DB_PORT` | `1433` | стандартный порт SQL Server |
| `DB_USER` | `sa` | стандартный админ SQL Server |
| `DB_PASSWORD` | твой пароль | пароль от `sa` |
| `DB_DATABASE` | `ArtistMerchDB` | имя базы |
| `DB_TRUST_SERVER_CERTIFICATE` | `true` | для локальной разработки — всегда true |
| `DB_INSTANCE` | `SQLEXPRESS` | только если SQL установлен как именованный инстанс (способ Б, шаг 5-вариант-2) |

## Часть 1. Способ А — Docker (рекомендую)

Плюс способа: ничего не надо устанавливать руками, база поднимается сама,
миграции (создание таблиц + тестовые данные) применяются сами.

### Шаг 1. Поставь Docker Desktop

Скачай с <https://www.docker.com/products/docker-desktop/>, установи, запусти.
В трее должен появиться значок кита, а команда `docker --version` в терминале —
ответить версией. Если кит просит включить WSL2 — согласись и перезагрузи ПК.

### Шаг 2. Подними всё приложение

Открой терминал **в корне проекта** (там, где лежит `docker-compose.yml`) и выполни:

```bash
docker compose up --build
```

Что произойдёт (это нормально, просто жди):

1. Соберётся образ базы (`db/Dockerfile` — это официальный SQL Server 2022,
   в который добавлен скрипт-инициализатор).
2. Соберутся образы бэкенда и фронтенда.
3. Контейнер базы стартует; внутри него скрипт подождёт, пока SQL Server проснётся
   (~20–60 секунд в первый раз), и **сам** выполнит `01_schema.sql` и `02_seed.sql`.
   В логах увидишь строки `[init] applying ...` и `[init] database initialized.`
4. Бэкенд подключится к базе (у него в compose уже прописано `MOCK_DB=false`,
   `DB_SERVER=db`, пароль `DevPassw0rd!`).

Терминал не закрывай — там живут логи. Открой **три** вкладки браузера:

- <http://localhost:4000/api/health> → `"connected": true, "mode": "mssql"` ✅
- <http://localhost:4000/api/products?limit=3> → товары из базы ✅
- <http://localhost:8080> → твой фронтенд, он теперь ходит в реальный API ✅

### Шаг 3. Посмотри данные руками (необязательно, но прикольно)

Порт 1433 проброшен на твой компьютер, поэтому базу видно из SSMS как обычную:
Server name `localhost,1433` (именно с запятой), аутентификация SQL Server,
логин `sa`, пароль `DevPassw0rd!`. Раскрой `ArtistMerchDB → Tables` — там твои
`Product`, `Orders` и всё остальное, с данными из сида.

### Шаг 4. Управление

```bash
# остановить всё (данные базы сохранятся)
docker compose down

# запустить снова (уже без --build, секунды)
docker compose up

# посмотреть, что база говорит (если что-то пошло не так)
docker compose logs db

# ПОЛНЫЙ сброс базы к заводскому состоянию (удалит все твои тестовые заказы!)
docker compose down -v
docker compose up --build
```

> Если контейнер базы падает по памяти: SQL Server хочет ~2 ГБ. В Docker Desktop:
> Settings → Resources → поставь Memory ≥ 4 GB.

Готово — база подключена. Часть 2 можешь не читать.

## Часть 2. Способ Б — без Docker (SQL Server Express + SSMS)

Это путь «как в методичках»: ставим SQL Server прямо в Windows.

### Шаг 1. Установи SQL Server Express и SSMS

1. <https://www.microsoft.com/ru-ru/sql-server/sql-server-downloads> → раздел
   Express → «Скачать». Запусти установщик → **Basic**.
2. В конце установки будет кнопка «Установить SSMS» — она ведёт на скачивание
   SSMS (Management Studio — программа, в которой смотрят базы). Установи и её.

Запомни: после установки у тебя стоит **именованный инстанс** `SQLEXPRESS`.

### Шаг 2. Разреши вход по логину/паролю (mixed mode)

По умолчанию SQL Server пускает только Windows-аккаунты, а бэкенд пойдёт
под пользователем `sa`. Включаем оба способа:

1. Открой SSMS. Server name: `localhost\SQLEXPRESS`, аутентификация:
   **Windows Authentication** → Connect.
2. В Object Explorer кликни правой кнопкой по самому верхнему пункту
   (имя сервера) → **Properties** → вкладка **Security** → отметь
   **SQL Server and Windows Authentication mode** → OK.
3. Изменения применятся после перезапуска службы: Win+R → `services.msc` →
   найди **SQL Server (SQLEXPRESS)** → правой кнопкой → **Restart**.

### Шаг 3. Задай пароль для sa

1. В SSMS: раскрой **Security → Logins** → правой кнопкой по **sa** → Properties.
2. Вкладка General: вбей пароль, например `DevPassw0rd!` (повтори в обоих полях).
   Если ругается на сложность — сними галочку **Enforce password policy**.
3. Вкладка **Status**: Login → **Enabled** → OK.

### Шаг 4. Открой порт 1433 (самый частый камень преткновения!)

Именованный инстанс по умолчанию слушает случайный порт — бэкенд его не найдёт.
Заставим его слушать стандартный 1433:

1. Пуск → найди **SQL Server Configuration Manager** (в папке Microsoft SQL Server 2022).
2. Слева: **SQL Server Network Configuration → Protocols for SQLEXPRESS**.
3. Справа по **TCP/IP** → правой кнопкой → **Enable**.
4. Дважды кликни по TCP/IP → вкладка **IP Addresses** → прокрути в самый низ
   до блока **IPAll**: поле **TCP Dynamic Ports** оставь пустым, в **TCP Port** впиши `1433` → OK.
5. Снова перезапусти службу **SQL Server (SQLEXPRESS)** в `services.msc`.

Проверка порта: в терминале `netstat -an | findstr 1433` — должна быть строка
`LISTENING` на `0.0.0.0:1433`.

### Шаг 5. Создай базу и таблицы

1. SSMS → меню **File → Open → File** → выбери `backend/sql/01_schema.sql` →
   кнопка **Execute** (или F5). Внизу появится «Commands completed successfully».
2. То же самое с `backend/sql/02_seed.sql`.
3. В Object Explorer правой кнопкой по **Databases** → **Refresh** — появится
   `ArtistMerchDB` с таблицами.

### Шаг 6. Настрой бэкенд

Открой `backend/.env` и поставь:

```ini
MOCK_DB=false
DB_SERVER=localhost
DB_PORT=1433
DB_USER=sa
DB_PASSWORD=DevPassw0rd!
DB_DATABASE=ArtistMerchDB
DB_TRUST_SERVER_CERTIFICATE=true
```

(это вариант 1 — с портом 1433, который мы открыли в шаге 4).

**Вариант 2** (если шаг 4 делать не хочешь): оставь `MOCK_DB=false`, но вместо
порта напиши `DB_INSTANCE=SQLEXPRESS` — бэкенд сам найдёт инстанс через
SQL Browser. Работает, если служба **SQL Server Browser** запущена
(в `services.msc` у неё тип запуска стоит «Automatic» и она стартовала).

### Шаг 7. Запусти и проверь

```bash
cd backend
npm run dev
```

Открой <http://localhost:4000/api/health> → `"connected": true, "mode": "mssql"`.
Затем <http://localhost:4000/api/products?limit=3> — увидишь товары из сида.

## Часть 3. Доказательство, что это НАСТОЯЩАЯ база

Сделай один простой эксперимент — и все сомнения уйдут:

1. В SSMS выполни:

   ```sql
   USE ArtistMerchDB;
   UPDATE Product SET Price = 999 WHERE Title LIKE N'Акриловый стенд "Странник"';
   ```

2. Обновий в браузере <http://localhost:4000/api/products/1> — цена станет 999.
3. Верни назад: `UPDATE Product SET Price = 750 WHERE ProductID = 1;`

Бэкенд читает то же, что лежит в SSMS — значит, подключение настоящее, а не мок.

## Часть 4. Если что-то пошло не так

| Что видишь | Что это значит и что делать |
|---|---|
| `/api/health` отвечает `"mode": "mock"` | В `.env` всё ещё `MOCK_DB=true`, либо бэкенд не перезапускали после правки `.env`. Останови `npm run dev` (Ctrl+C), запусти снова. |
| `Failed to connect to localhost:1433 ... ECONNREFUSED` | SQL Server не запущен или TCP/IP не включён (способ Б: шаги 2 и 4, перезапуск службы!). При Docker — кит не запущен: `docker compose ps`. |
| `Login failed for user 'sa'` (ошибка 18456) | Неверный пароль, либо не включён mixed mode (шаг 2), либо у sa стоит Status = Disabled (шаг 3). |
| `Cannot open database "ArtistMerchDB"` | База не создана: выполни `01_schema.sql` и `02_seed.sql` в SSMS (шаг 5). |
| Docker: контейнер db всё время restarting | Мало памяти — подними лимит в Docker Desktop до 4+ ГБ. Смотри `docker compose logs db`. |
| Docker: логи db содержат `[init] ERROR` | Скрипт миграции упал — посмотри строку выше; чаще всего это повторный закат на непустую базу. Лечится `docker compose down -v`. |
| Фронт показывает старые данные | Убедись, что фронт ходит в тот же бэкенд: на dev-сервере Vite прокси `/api` → `localhost:4000` (см. FRONTEND.md), а health отвечает `mssql`, а не `mock`. |
| `netstat` не показывает 1433 | Шаг 4 не применился — проверь, что служба перезапускалась ПОСЛЕ правки TCP/IP. |

Общее правило отладки: смотри **текст ошибки** в ответе `/api/health` или в консоли
бэкенда — бэкенд печатает `[db] не удалось подключиться...` с причиной, и она почти
всегда совпадает с одной из строк таблицы выше.

## Часть 5. Как вернуться на заглушки

В `.env` поставь `MOCK_DB=true`, перезапусти бэкенд. Полезно, когда базы под рукой нет
(ноут без Docker в дороге), а фронт разрабатывать надо.
